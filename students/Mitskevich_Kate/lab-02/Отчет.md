### Часть 3. Domain Layer (Доменный слой)

#### Доменные сущности

**1. Transaction (Транзакция) - Aggregate Root**

**Идентификатор:** `TXN-2024-0042`

**Атрибуты:**
```python
class Transaction:
    id: str                      # TXN-YYYY-XXXXX
    type: TransactionType        # INCOME или EXPENSE
    amount: Decimal              # Сумма (> 0)
    user_id: str                 # ID пользователя
    description: Optional[str]   # Комментарий
    category_distributions: List[CategoryDistribution]  # Распределение по категориям
    status: TransactionStatus    # PENDING, COMPLETED, FAILED
    idempotency_key: str         # Для предотвращения дублирования
    created_at: datetime
    updated_at: datetime
```

**Бизнес-правила:**
- Для INCOME: сумма распределения по категориям = total amount
- Для EXPENSE: сумма списания не может превышать баланс категории (с предупреждением)
- Статус: PENDING → COMPLETED/FAILED
- Одна транзакция может затрагивать несколько категорий

**2. Category (Категория) - Entity**

**Идентификатор:** `CAT-01`

**Атрибуты:**
```python
class Category:
    id: str
    name: str                    # "Покушать", "Накопления"
    user_id: str
    balance: Decimal             # Текущий баланс
    budget_percentage: Decimal   # Процент от дохода (0-100)
    created_at: datetime
    updated_at: datetime
```

**Бизнес-правила:**
- Название категории уникально для пользователя
- Сумма `budget_percentage` для всех категорий пользователя = 100%
- Баланс может быть отрицательным (с предупреждением)

**3. BudgetSetting (Настройка бюджета) - Value Object**

**Атрибуты:**
```python
@dataclass(frozen=True)
class BudgetSetting:
    category_id: str
    percentage: Decimal          # 0-100
    user_id: str
```

**Свойства:**
- Immutable (неизменяемый)
- Equality by value (сравнение по значению)
- Валидация при создании: 0 <= percentage <= 100

Интерфейс для регистрации дохода:

```python
class CreateIncomeUseCase(ABC):
    """Входящий порт для регистрации дохода"""
    
    @abstractmethod
    def create_income(self, command: CreateIncomeCommand) -> str:
        """
        Зарегистрировать доход и распределить по категориям
        
        Returns:
            ID созданной транзакции
        """
        pass
```

**Command DTO:**
```python
@dataclass
class CreateIncomeCommand:
    """Команда для регистрации дохода"""
    user_id: str
    amount: Decimal
    description: Optional[str]
    idempotency_key: str
    source: Optional[str]        # "Зарплата", "Фриланс" и т.д.
```

```python
class CreateExpenseUseCase(ABC):

    @abstractmethod
    def create_expense(self, command: CreateExpenseCommand) -> str:
        """
        Зарегистрировать расход из указанной категории
```

#### Исходящие порты (Outbound Ports)
Интерфейсы, через которые система взаимодействует с внешним миром:

**1.TransactionRepository**

Интерфейс для работы с хранилищем транзакций:

```python
class TransactionRepository(ABC):
    """Исходящий порт для работы с транзакциями"""
    
    @abstractmethod
    def save(self, transaction: Transaction) -> None:
        """Сохранить транзакцию"""
        pass
    
    @abstractmethod
    def find_by_id(self, transaction_id: str) -> Optional[Transaction]:
        """Найти транзакцию по ID"""
        pass
    
    @abstractmethod
    def find_by_idempotency_key(self, key: str) -> Optional[Transaction]:
        """Найти транзакцию по ключу идемпотентности"""
        pass
```

**2.CategoryRepository**


```python
class CategoryRepository(ABC):
    """Исходящий порт для работы с категориями"""
    
    @abstractmethod
    def find_by_id(self, category_id: str) -> Optional[Category]:
        """Найти категорию по ID"""
        pass
    
    @abstractmethod
    def find_by_user_id(self, user_id: str) -> List[Category]:
        """Найти все категории пользователя"""
        pass
    
    @abstractmethod
    def update_balance(self, category_id: str, new_balance: Decimal) -> None:
        """Обновить баланс категории (с блокировкой)"""
        pass
```

**3.BudgetSettingsRepository**

Интерфейс для работы с настройками бюджета:

```python
class BudgetSettingsRepository(ABC):
```

# Описание портов и адаптеров

## Входящие порты (Inbound Ports)

| Тип | Название | Назначение |
|-----|----------|------------|
| **Входящий порт** | `CreateIncomeUseCase` | Интерфейс для регистрации дохода пользователя. Определяет метод `create_income(command)`, который принимает команду с суммой дохода и автоматически распределяет её по категориям согласно настройкам бюджета пользователя. Возвращает ID созданной транзакции. |
| **Входящий порт** | `CreateExpenseUseCase` | Интерфейс для регистрации расхода. Определяет метод `create_expense(command)`, который списывает указанную сумму с баланса выбранной категории. Возвращает ID созданной транзакции и проверяет, не уходит ли баланс категории в минус (с возможностью разрешить отрицательный баланс). |

## Исходящие порты (Outbound Ports)

| Тип | Название | Назначение |
|-----|----------|------------|
| **Исходящий порт** | `TransactionRepository` | Интерфейс для работы с хранилищем транзакций. Предоставляет методы: `save()` - сохранение транзакции, `find_by_id()` - поиск по ID, `find_by_idempotency_key()` - поиск по ключу идемпотентности для предотвращения дублирования операций. |
| **Исходящий порт** | `CategoryRepository` | Интерфейс для работы с категориями пользователя. Предоставляет методы: `find_by_id()` - поиск категории по ID, `find_by_user_id()` - получение всех категорий пользователя, `update_balance()` - атомарное обновление баланса категории с блокировкой для избежания race condition. |
| **Исходящий порт** | `BudgetSettingsRepository` | Интерфейс для работы с настройками бюджета. Предоставляет методы: `find_by_user_id()` - получение настроек распределения доходов пользователя, `validate_percentage_sum()` - проверка, что сумма процентов распределения дохода равна 100%. |

## Входящие адаптеры (Inbound Adapters)

| Тип | Название | Назначение |
|-----|----------|------------|
| **Входящий адаптер** | `TransactionController` (REST API) | HTTP-контроллер на FastAPI, который принимает REST-запросы от клиентов. Преобразует JSON-запросы в команды (`CreateIncomeCommand`, `CreateExpenseCommand`), вызывает соответствующие use-case, и возвращает HTTP-ответы с результатом операции. |
| **Входящий адаптер** | `CLI` (опционально) | Простой интерфейс командной строки для тестирования и демонстрации работы сервиса без необходимости запускать HTTP-сервер. |

## Исходящие адаптеры (Outbound Adapters)

| Тип | Название | Назначение |
|-----|----------|------------|
| **Исходящий адаптер** | `PostgresTransactionRepository` | Реализация `TransactionRepository` для PostgreSQL. Сохраняет транзакции в таблицу `transactions`, выполняет поиск по ID и по ключу идемпотентности. Использует транзакции БД для обеспечения атомарности операций. |
| **Исходящий адаптер** | `PostgresCategoryRepository` | Реализация `CategoryRepository` для PostgreSQL. Управляет таблицей `categories`, обновляет балансы категорий с использованием SELECT FOR UPDATE для блокировки строк и предотвращения конкурентных изменений. |
| **Исходящий адаптер** | `PostgresBudgetRepository` | Реализация `BudgetSettingsRepository` для PostgreSQL. Хранит настройки бюджета в таблице `budget_settings`, выполняет валидацию суммы процентов при изменении настроек. |

## 6. Выводы

### Что получилось хорошо

> Удалось чётко отделить бизнес-логику (Order, Money) от инфраструктуры. Domain слой не имеет зависимостей от Spring или БД аннотаций. OrderService легко тестируется с моками.

### С какими трудностями столкнулись

> Было сложно понять, зачем создавать интерфейс для порта, если у него только одна реализация. После изучения статьи про Dependency Inversion стало ясно: это для тестируемости и возможности замены адаптера.

### Что узнали нового

> Изучил принцип Dependency Inversion: domain не зависит от деталей реализации. Понял, как гексагональная архитектура упрощает замену БД или UI без изменения бизнес-логики.

### Как можно улучшить

> Добавить реальную БД (PostgreSQL), реализовать EventBus для асинхронных уведомлений, написать интеграционные тесты с TestContainers.
